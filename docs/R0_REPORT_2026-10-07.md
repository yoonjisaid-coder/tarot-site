## Vercel preview deployment (diagnosed 2026-10-08)

Source: Vercel build log of `dpl_A8N4KMosnGJFHR2fKG4rz8qF5g8i` (branch commit 8a2a2a1). `pnpm run build` → `vinext build` completes ("Build complete"). The step after it fails: `The file "/vercel/path0/.next/routes-manifest.json" couldn't be found`.

Cause: the Vercel project's framework preset is `nextjs` (auto-detected from the `next` dependency), so Vercel post-processes a Next.js `.next/` output. This app is built by vinext for Cloudflare Workers (`dist/`, `@cloudflare/vite-plugin`, wrangler; hosting is ChatGPT Sites per `.openai/hosting.json`). Every Vercel deployment of this repo has failed the same way, including the main production deployment of a906487, so this is not a regression from this branch.

No code/config change made: switching the preset to static output would not serve the SSR routes (`/reading/:slug`, `/card-meanings/:slug`). Making Vercel work requires a Vercel adapter for vinext, i.e. hosting migration — outside R0, needs a decision.

## Interpretation quality rework #2 (2026-10-08)

Root cause: the KO engine built every reading from per-card glossary text (`card.upright/reversed`, `cardScene`) plus a 3-way tone lens per question. Card evidence and advice ignored the question type, the conclusion averaged card tone, the third (advice) card was read as a prediction, and timing existed only in four single-card timing questions.

New architecture (`lib/reading-engine.ts`, `lib/reading-voice-*.ts`): question → question type (contact, reunion, feelings, progress, decision, wait-or-let-go, self) and position roles (signal / obstacle / advice / past-now-next) → each card mapped to one of 12 reading classes plus its picture → verdict level (HIGH / DELAY / MIXED / LOW / FOG) from role-weighted class polarity, obstacle severity and outcome progression → direct answer per question → per card: question-type-specific claim, picture-based evidence, situation, action → spread synthesis that follows the verdict and reconciles a conflicting advice card → timing range with confidence for contact / reunion / progress questions → deciding factor → next step. English keeps the previous engine.

Timing: `lib/timing.ts` keeps its band logic (624-combination gate unchanged) but answers in event-appropriate units (contact: days–weeks, reunion/new love: months) with early/late edges and a confidence note; three-card questions get a range from the pace of the non-obstacle cards, are withheld when the verdict is low or unclear, and never produce dates.

Verification: `check-reading-quality.cjs` (new; 3,504 readings: genericity across question types, repetition, register, fabrication patterns, timing ranges, progression) PASS — the same harness flags 10 regression categories on the pre-rework code. `check-reading-text.cjs` 8,400 PASS, `check-timing.cjs` 624 PASS, build PASS, journey E2E PC 29/29 and mobile 32/32. Before/after for 16 fixtures and a self-assessed rubric: `docs/quality/R2_REVIEW.md`.

## Interpretation R3 — final editorial pass (2026-10-08)

Human review of R2 found four defects; R3 keeps the R2 architecture and fixes only those.

1. Card semantic integrity: `lib/card-cores.ts` gives all 78 cards × 2 orientations a semantic core, an obstacle form and an advice form. Evidence always states the core; the obstacle one-liner and the synthesis use the card's own obstacle; the advice one-liner is the card's own advice applied to the question. The 12 classes became an auxiliary feature (polarity, pace) plus a 13th class (EXPECT: unmet expectations/illusion) for cards the old classes distorted, e.g. 9 of Cups reversed is now "채워지지 않는 기대 / 앞서가는 기대", not "정보 부족".
2. Consistency: wait-or-let-go now treats memory and expectation as reasons to let go (they were scored as reasons to wait while the evidence argued the opposite); mixed let-go readings get a conditional answer with a short deadline. `scripts/check-reading-consistency.cjs` (4,403 readings) checks core-in-evidence, one obstacle name across claim and synthesis, verdict vs evidence direction, acknowledged advice tension, advice-card action in the synthesis and answer/body timing agreement.
3. Template smell: removed "결과를 바꿀 수 있는 가장 큰 변수는…", "그 사이에서 …를 권해요", "…라는 조언이에요", "그려져 있어요", fixed obstacle closings; synthesis structure now depends on verdict level and card relationship. The quality harness bans those frames and fails any sentence that appears in more than 8% of readings.
4. Timing: shows one most-likely window plus confidence (높음/보통/낮음) and the card-based basis; documented as UNTOLD's editorial convention in `docs/TIMING_READING_RULES.md`.

Answer headings show a verdict label (e.g. "질문에 대한 답 · 조건부").

Verification: typecheck, build, check-reading-quality (3,504) PASS, check-reading-consistency (4,403) PASS, check-reading-text (8,400) PASS, check-timing (624) PASS, journey E2E PC 29/29, mobile 32/32. Human review set: `docs/quality/R3_REVIEW.md` (20 readings, not self-scored).

INTERPRETATION QUALITY: pending human editorial review. R0 overall: FAIL until production deployment and real-device QA.
